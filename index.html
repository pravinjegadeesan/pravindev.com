About the developer

An independent project, built in the open.

I’m the independent developer behind RepoLens, exploring how to make unfamiliar codebases easier to understand. I’m building the project step by step, starting with a small, testable scope and sharing progress as it takes shape.

Design principles

The goal is to support developers' judgment, not replace it: show evidence, make uncertainty visible, and keep people in control.

01 /

Evidence before confidence

Link explanations to relevant files and make uncertainty visible instead of presenting guesses as facts.

02 /

Human review by default

Generated documentation should be editable and reviewable before it is shared or committed.

03 /

Privacy-conscious processing

Define repository access, retention, and secret-handling rules before processing private code. Never upload private source code without informed authorization.

04 /

Small, testable scope

Start with public repositories and a limited set of outputs; measure usefulness before expanding the feature set.

Build in public

A focused path to an MVP.

Milestones will be marked complete only after the work exists in the repository and can be verified.

Milestone 01 · Planned

Safe local repository scanner

Define supported file types; skip secrets, binaries, dependency folders, and oversized files; produce a deterministic file-tree summary; cover behavior with sample-project tests.

Milestone 02 · Planned

Evidence-grounded file explanations

Prototype summaries for selected files with source-path references, bounded context, clear errors, and documented privacy limits.

Milestone 03 · Planned

Editable exports and evaluation

Export reviewable Markdown, compare results against a small test set, and publish known limitations before broadening the scope.
